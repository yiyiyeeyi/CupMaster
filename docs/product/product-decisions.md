## 1. 依據的優先順序

衝突時由上往下：

1. **使用者最新、明確的指示**
2. **`AGENTS.md` 的產品與安全不變式**（例如不可捏造量測值、Bean 不得成為開始沖煮的前提）
3. **本檔與 Notion PRD**：產品範圍、流程、版本歸屬
4. **`design/`**：版面、資訊層級、元件位置、字級、按鈕位置。不得自行重新設計。
   但設計圖中**已過時的元素以產品規則為準**：五分頁導覽、必填咖啡豆／器材、AR／相機畫面、Collection 優先、未實作的 AI／聊天動作、捏造的量測值。
5. **`docs/` 其他文件**：工程細節（資料模型、狀態機、合約）
6. **程式碼現況**

發現衝突時，不要自行選邊：記到 Notion「決策與待決問題」並回報使用者。

## 3. 產品定位

CupMaster 是 **AI 視覺輔助的手沖咖啡教練**（mobile-first PWA）。不是食譜收藏、不是單純計時器、不是要先填完資料才能用的資料庫。

核心循環：**快速開始 → 跟著引導沖 → 保存 → 事後回顧 → 用聚焦的下一杯改善 → 第二杯**。

目標使用者：在家自學的新手（V1 主要）、想改善的進階者（V1 次要）、咖啡店員工培訓（V2，B2B）。不服務已經是大師的人，但要能帶人往大師走。

## 4. 版本範圍

### V1：把完整一輪跑通（目前唯一目標）

**完整旅程以 `docs/product/user-journey-v1.md` 為準**（2026-10-24 定案）。

Discover → Recipe Detail → Quick Prepare → Live Brew → Brew Detail（剛完成）→ 回饋／補資料／Analysis → 再沖一杯 → Quick Prepare → 第二杯。不強迫登入與 Onboarding。

V1 必須做到：

- 相機、光引導、語音改為 Live Brew 開關列，沖煮中可切（2026-10-24）；以下為 REQ-3 已實作的基礎行為。
- 相機權限被拒或不支援時，有完整的手動替代流程：只用計時與語音也能沖完並儲存。即使相機可用，也可在相機對位畫面主動選擇「不用相機，只用計時與語音」；入口沿用既有設計位置，不新增版面區塊。
- 暫停／重來後，儲存的時間與實際一致。「重來」清除本次執行時間與階段結果，保留同一筆 Brew 與原 Snapshot，不另建新 Brew。
- 儲存失敗（含階段完成時）可重試，紀錄不會丟失。
- ~~「再沖一次（Brew Again）」~~：已由「再沖一杯」取代（見 user-journey-v1.md 第 3 節）。
- 光引導：依大師軌跡在畫面上播放流動的光，使用者跟著最亮點繞。**V1 只播放，不判斷使用者是否跟上。**
- 濾杯對位框可拖拉調整，ROI 與畫面 `object-fit: cover` 正確換算。
- 資料模型預留錄影與軌跡的**選填**欄位，舊資料不受影響。
- PWA manifest 與 service worker；iPhone 與 Android 實機走完全流程。
- 介面文案統一為**繁體中文**，品牌名稱與標準頁名保留英文；文案抽成可翻譯字串。

V1 成功標準：

1. 產品負責人本人走完「第一杯 → 回顧 → 第二杯」，全程無卡關。
2. 沒沖過手沖的朋友，不看說明，**10 分鐘內完成第一杯**。

### V1.5：影像辨識進入產品

- 即時軌跡判斷與教練回饋（有容錯：「可以慢慢往內收」「現在有點太靠外」；不確定時寧可不說）。
- 軌跡記錄（自選）：沖煮前開關「記錄這次的軌跡」（預設關）→ 沖煮中只錄影 → **沖完後**從錄影挑一張畫面點選壺嘴 → 離線產生軌跡 → 可存成自己的方案。
- 大師影片軌跡擷取工具（內部），與上面共用同一套流程。
- 真 AI 分析。

### V2：擴展與商業化

器材引導與知識庫（切片 3）、探索與收藏（切片 4）、電子秤與相機讀秤、登入＋雲端同步＋付費訂閱、器材導購、拍照判斷研磨度、咖啡店培訓、多語系切換（繁中／英文／簡中）。

### 長期

自有硬體：電子秤、感測濾杯（流速、TDS、酸鹼、濃度）、手沖壺感測器（傾斜角度）。

## 5. 明確不做（目前）

- 硬體
- 任意相機角度（V1 限定近俯視，約 85–90 度）
- 自動理解整個場景（接受手動濾杯校正）
- 像素級精準軌跡、三維重建、完整分割
- 沖煮中每幀呼叫 AI
- 支援所有咖啡壺（V60 類優先）
- V1 的購物結帳、聯盟行銷、強制校準、強迫登入

- 壺嘴貼色帶作為保底方案是否可接受
